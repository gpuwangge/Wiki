# Clip介绍
Clip出现的位置: mvp之后，ndc/viewport变换/ras之前。  

Clip Space：Pclip  
Pclip=MVP*p_model  

Clip就是把位于Clip Space之外的几何部分除去。  
举例：一个巨大的三角形，只有一小部分在屏幕里。如果不clip，就必须做完整三角形的光栅化。clip把这个巨大的三角形裁剪成合法范围内的小多边形，节省渲染成本。  

# Clip分类
- View Frustum Clipping 视锥裁剪  
- Near Plane 近裁剪面  
- Viewport 视口  
首先这个不是Viewport变换   
Viewport的定义是(0,0,width,height)  
也叫隐式裁剪  

- Scissor 剪刀  
跟viewport比，这是一个更小的矩形区域  

Clip不是Cull，前者是切成小多边形，后者是完全丢弃。一般先做cull再做clip。  


# Sutherland-Hodgman
什么是barycentric coordinate based variant of the Sutherland-Hodgman polygon clipping algorithm  
以下简称SH算法。  
SH是一个几何裁剪算法。输入是多边形和一个凸裁剪区域。输出是新的多边形顶点序列。  
- 外循环遍历裁剪区域的每个平面  
- 对每个平面，内循环遍历多边形的每条边，在跨越平面的边上计算交点（新顶点）  

算法特点：  
- 按平面顺序，按边分类，按需求交  
- 过程中始终维护一个“当前裁剪结果”的顶点列表  
 
# Signed Distance P
在判断顶点在裁剪平面内侧或外侧的时候，并且计算交点的时候，常需要计算signed distance P。  
设平面方程Ax+By+Cz+D=0, normal为(A,B,C), 并且normal是个单位向量。(当D为0的时候，平面通过原点）  
设定normal的正方向为内侧inside，负方向为外侧outside  
假设有一点v0=(x0,y0,z0)，代入方程为  
P(v0)=Ax0+By0+Cz0+D, 简记为P  
如果P刚好是0，说明v0位于平面上。  
P>0和P<0表示v0分别位于外侧和内侧。证明思路是平面方程是个连续函数，某个点从一侧穿过平面到另一侧一定是要经过平面的(也就是P为0的那个点)。由因为我们规定normal正方向为内侧，所以P>0就代表v0在内侧。  
另外，可以证明P的绝对值就是P到平面的最短距离。注意的是这一点只有在normal是单位向量的时候成立，如果不是单位向量要通过normal的模计算真正的distance。  

# 视锥体
假设clip空间下有一个点  
v=PVM cdot (x y z 1) = (X Y Z W)  
这时候进入裁剪步骤  
这里X Y Z W是clip space顶点的齐次坐标分量  
其中，W决定了透视投影的远近缩放效果，远处的W大，X Y除以W后就变得更小，更加靠近屏幕中心，造成近大远小效果。  
具体来说，满足下面不等式代表了在视锥体内：  
-W<=X<=W  
-W<=Y<=W  
-W<=Z<=W  
变换后的clip space里，视锥体的6个平面可以写成：  
• Left: X + W = 0  
• Right: W - X = 0  
• Bottom: Y + W = 0  
• Top: W - Y = 0  
• Near: Z + W = 0  
• Far: W - Z = 0  

考虑guardband可以写成：  
| Plane | P-Value Formula | Guardband |
|-------|------------------|-----------|
| Left | `P = 1.5 * W + X` | Yes |
| Right | `P = 1.5 * W - X` | Yes |
| Bottom | `P = 1.5 * W + Y` | Yes |
| Top | `P = 1.5 * W - Y` | Yes |
| Back | `P = W - Z` | No (1×W) |
| Front (OpenGL) | `P = W + Z` | No (1×W) |
| Front (non-OGL) | `P = Z + 0` | No (0×W) |

这张表里的 “1.5W” 到底扩大了什么  
- 它表示 X/Y 的 clip 边界从 ±W 放宽到 ±1.5W（Z 不变）。  
- 在 NDC 里等价于：  
x、y 的有效范围从 [-1,1] 扩到 [-1.5,1.5]。  
- 所以：  
• 单边界位置：扩大 50%（对）  
• 宽度：扩大 50%（对）  
• 屏幕平面面积：扩大到 2.25 倍（增加 125%）  
• FOV：不是扩大 50%，而满足  
tan(θ'/2) = 1.5 tan(θ/2)   

为什么 GPU 要在 clip space 用这些简单形式裁剪？  
原因很实际：  
1. 硬件裁剪要高效、统一：  
- 不管你相机 FOV、near/far 怎么变；  
- 对硬件来说，裁剪规则永远是：  
-W ≤ X ≤ W，  
-W ≤ Y ≤ W，  
-W ≤ Z ≤ W。  
2. 投影矩阵由你（应用）决定：  
- 你调 FOV、near/far，本质上就是改投影矩阵的内容；  
- 矩阵变了之后，同一个世界中的点会变成不同的 (X,Y,Z,W)，  
于是对应不同的裁剪结果。  
3. 裁剪阶段只负责“标准化后的视锥体”：  
- GPU 不关心你是 60° FOV 还是 90° FOV；  
- 它只看投影后的点是不是在标准视锥体里。  

换句话说：  
FOV / near / far 决定的是“投影矩阵长什么样”；  
投影矩阵又决定了“世界点在 clip space 中的 X/Y/Z/W”；  
最终裁剪用的是 X/Y/Z/W 是否满足标准盒子内的条件，  
这就是 X+W、W-X 等形式的来源。  

# Guardband
概念整理  
实际屏幕：物理设备上的所有像素。  
窗口：操作系统在屏幕上分配的一个区域。全屏模式就是覆盖整个屏幕。一个窗口对应一个framebuffer，这个framebuffer也叫render target。  
Viewport：framebuffer上的一个矩形区域。  
Guardband：viewport的区域向外扩展一圈，成为guardband区域。viewport之外，guardband之内的区域在写入阶段会被丢掉，不会写入颜色和深度缓冲。  
Guardband的用处：减少viewport边缘的裁剪。  

# Clip算法分析  
三角形，guardband，考虑交点都在一个裁剪平面  
- 全在内：不裁剪  
- 全在外：整个三角形丢弃。但有一种少见情况，就是所有点在外，但三角形仍与裁剪区域有交集。  
- 两点在内，一点在外：得到一个四边形，之后再三角形化  
- 一点在内，两点在外：得到一个较小的三角形  

假设三角形ABC，A在内，BC在外。在AB、AC上分别求与裁剪点的交点l1、l2。新三角形为A-l1-l2。  
假设三角形ABC，A、B在内，C在外，在AC、BC上求交点l1、l2，四边形为A-B-l1-l2。  
考虑交点分别在两个裁剪平面，会多出一个顶点，新图形为四边形或五边形。  
考虑交点在两个裁剪平面，两平面间有第三个平面，新图形为五边形或六边形。如果夹了两个平面，甚至可以是六边形或七边形。  
但有可能交点不止两个  

标准方法是按照裁剪平面以此裁剪。比如视锥体是六个平面，SH算法会对每个裁剪平面以此裁剪。  
三角形输入  
对第一个裁剪平面裁剪，结果可能是0/3/4变形  
把上一步的结果对第二个裁剪平面裁剪，结果可能是0/3/4/5边形  
。。。以此类推  
但上限是六边形。为什么呢？  
就好像拿刀去削一个三角形木板，一开始很容易削出更多的点，但削的次数多了以后，可能把原本生成的点也削掉，所以顶点数不会一直增长。  
对视锥体来说，初始三角形削成四边形，之后左右各削一次，变成六边形。之后该上下(top and down)削了，会影响到之前左右削出来的顶点。  

为什么上限是六边形不是七边形？  
六边形是经验公式，严格证明比较繁琐。  
实现的时候数组一般定七个。  
冗余保安全。  

# Depth clamping
在裁剪的时候，本来视锥体两个z平面会参与裁剪。但在开启了depth clamping之后，这两个平面不参与裁剪；并且在ras之后，裁剪平面之外的像素的深度值被clamp在视锥体之内。  
第一，开启了depth clamping之后，几何体在极近或极远的地方也可以正常渲染。这里有个问题，如果想渲染极近或极远的几何体，把视锥体的z-near拉近，z-far拉远不就行了吗？还真不行。因为视锥体z方向太宽，会导致z test精度下降，特别是在远端频繁出现z fighting现象。所以不能用改变视锥体形状的办法。  
例子：fps的枪械，背景无限远的天空。shadowmap的时候阴影camera也会开启depth clamping。  
第二，ras之后，在后续计算depth testing的时候，视锥体以外的几何体的像素会按照z-near和z-far的值来计算。  
什么情况不适合开depth clamp：比如医学可视化只想看某个切片内的状况。还有就是需要利用深度做一些景深效果的时候，如果开了depth clamp，视锥体外的物体的深度就会好像贴在z-near和z-far上，导致不正确的结果。  
另一个问题：超出视锥体（比如远处）的几何体z都被clamp到一个值（比如z-far），那会不会在z-far处出现z fighting？理论上会。但实际上，好的设计不会让很多几何体出现在视锥体之外，一般出现在视锥体之外的是远景图、skybox之类的少数特殊物体。即使要放多个物体，也可以手动操作使其有确定的渲染次序，这样是可以避免z fighting的。
