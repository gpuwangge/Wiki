# GPU Model基本类型
| 类型                          | 核心问题                 | 主要建模内容                      | 通常省略什么                     | 主要使用阶段                    |
| --------------------------- | -------------------- | --------------------------- | -------------------------- | ------------------------- |
| Functional model，功能模型       | “结果算得对不对？”           | 指令、算法或接口的功能语义；输入如何变成输出      | 流水线、资源竞争、逐周期时序             | 规格定义、算法验证、软件提前开发，后续作为验证参考 |
| Performance model，性能模型      | “跑得多快？瓶颈在哪？怎么配置更划算？” | 延迟、吞吐、带宽、依赖、资源竞争等影响性能的因素    | 不影响目标性能指标的实现细节；有时不计算实际数据结果 | 架构探索、微架构权衡，后续与 RTL 校准     |
| Cycle-accurate model，周期精确模型 | “每个时钟周期发生什么？”        | 逐周期状态推进、发射、完成、阻塞和资源占用       | 可以省略门级逻辑、实际数据通路和部分信号细节     | 微架构设计、精细性能分析、时序行为对比       |
| RTL，寄存器传输级描述                | “用哪些寄存器和逻辑把它实现出来？”   | 寄存器、组合逻辑、状态机、数据位宽、时钟沿上的状态更新 | 布局布线、实际线延迟等物理细节            | 逻辑设计、功能验证、综合及后续物理实现       |

不同模型的抽象层次
| 对象                      | Functional model 需要保留什么              | 通常可以省略什么                               |
| ----------------------- | ------------------------------------ | -------------------------------------- |
| Cache                   | 软件可观察的访存、cache maintenance、非一致性访问等语义 | 容量、组相联、替换策略、hit/miss 延迟等纯微架构细节         |
| Atomics                 | 原子读改写、返回值，以及接口规定的作用域和顺序约束            | cache line ownership 转移、总线锁定或内部仲裁等实现机制 |
| 内存序（memory consistency） | load/store、fence、atomic 之间允许或禁止的可见顺序 | 实际流水线、store buffer 的逐周期实现              |
| 缓存一致性（cache coherence）  | 同一地址的数据可见性与写入顺序保证                    | 如果不显式建 cache，通常不必实现 MESI 等协议状态机        |

# 模型作为 golden reference：怎么和 RTL 做比对
## Trace compare：离线比较
```
同一初始状态 + 同一组输入
          ├── RTL   → actual.trace
          └── Model → expected.trace
                         ↓
                 normalize + compare
```

## Co-simulation：在线比较
```
RTL monitor → 事件 → reference adapter → 模型推进
                  └───────────────→ scoreboard
```
