# 指令集体系结构（Instruction Set Architecture, ISA）
ISA是Computer Architecture的最核心部分。它定义了软件与硬件之间的标准接口,换句话说就是描述了**汇编**程序员视角。  
并且ISA定义了汇编语言和编程模型。通过学习ISA可以了解计算机底层。  
ISA是抽象的，因为它没有考虑计算机的实现。
如果不是从程序员视角而是从计算机视角描述硬件就叫做组成原理(Organization)。  

ISA主要包括：  
- 指令集：CPU 能理解并执行的所有指令（如加减法、跳转、加载/存储）。
- 寄存器：软件可以直接使用的通用寄存器、状态寄存器等。
- 数据类型与表示：整数（补码）、浮点数（IEEE 754）、字符等在内存中的排列和大小。
- 寻址模式：指令如何找到内存中的操作数。  
- 内存模型与中断机制：虚拟内存结构、异常和中断的处理流程。

典型的 ISA 体系结构例子包括：
- x86-64（Intel/AMD 芯片）
- ARM（手机/M系列 Mac 芯片）
- RISC-V（开源指令集架构）

其他两个重要概念：
- 微体系结构(micro architecture, or uarch)：描述了指令集结构的实现方式，比如门电路。微体系结构关注计算机的内部设计。微体系结构是ISA的实现。  
- 系统体系结构：处理器，存储器，总线和外设。

计算机系统体系结构所涉及的内容：
Cache Memory <==> CPU <==> 系统总线 <==> 主存  
(CPU和主存是核心)  

系统总线(速度快) <==> 扩展总线接口、串行接口控制器 <==> 扩展总线(速度略慢) <==> IO控制器、磁盘驱动器、显示控制器  
(总线还链接其它接口)  

什么是计算机体系结构：包括CPU(Central Processing Unit，实际执行程序的部分), 存储器，以及输入输出子系统。  
微处理器: 是单个硅片上实现的CPU。  
微机: 围绕微处理器构建的计算机称作微机。  
信息: 程序和数据。  
寄存器(Register)：CPU内部用来存放数据的存储单元。速度最快。  
(但寄存器较小，如果寄存器不够用，会发生register spilling，就是实际走的是cache/ram，发生性能暴跌)
Cache：存放数据的高速专用存储器。CPU内集成了片上缓存。速度非常快。(L1$>L2$>L3$)  
主存(内存, RAM)： 存放了大量工作数据。速度很快。  
辅存：比如磁盘和CD-ROM，SSD, 能存海量数据。速度一般。  
时钟：提供脉冲流。所有内部操作都在时钟脉冲的触发下进行。时钟频率是决定计算机速度的一个因素。大多数数字电子电路都带有时钟，用以生成连续的、间隔固定的电脉冲流。  

寄存器：存放一个单位的数据，或字数据的存储单元。典型字有8、16、32和64位。  
寄存器和存储器中的字存储单元没有本质区别，区别是寄存器位于CPU内，它的访问速度远远快于访问CPU外的存储器。  

机器码：计算机上执行的二进制组成的串。每种计算机（INTEL、ARM...）只能执行一种特定的机器码。  
汇编语言：人类可读的机器码（比如ADD R0, R1）。  
高级语言：能在完全不同的计算机上执行、与底层计算机体系结构几乎没有关系的语言（C、Java...）。高级语言程序必须先被编译成计算机的本地机器码。 

## 程序执行的过程举例
```
Z = X + Y
```
先编译成机器指令，存储器内容如下：
```
//程序部分（一共四条指令）
LOAD X
LOAD Y
Z = X + Y
STORE Z
STOP
//数据部分
X //源操作数，入寄存器、入加法器(ALU的一部分)
Y //源操作数，入寄存器、入加法器
Z //目的操作数，出寄存器、出加法器
```

流程如下：
- 加载(Load)：把指令从存储器取出来到寄存器里，并通过解码器解释（发现这个指令需要两个源操作数）。把数据也从存储器加载到寄存器里。每一步都通过时钟触发。  
比如，LOAD A, X, Y分别加载到不同的寄存器里。  
- 然后ALU通过寄存器计算结果。  
- 存储(Store)：把ALU的计算结果存回存储器。  

计算机有上百条指令，但只有六条基本指令：
```
MOV A, B //B复制到A  
LOAD A, B //存储单元B复制到A  
STORE A, B //B复制到存储单元A  
ADD A, B //A+B，结果存到A  
TEST A //测试A是否为0  
BEQ Z //若最后一次测试结果为TRUE，则执行地址Z处的代码，否则继续执行  
```

## 寄存器传输语言(Register Transfer Language, RTL)
由于是用文字描述计算机的操作很不方便，使用RTL可以更加容易地定义计算机内发生的操作。  

### RTL符号  
区分存储单元的地址和它的内容非常重要。在RTL中，用方括号[]表示存储单元的内容，如  
```
[15] = Max_Run
```
含义是：地址为15的存储单元保存了变量Max_Run的值。  
左箭头符号表示数据传输操作，如  
```
[15]<--[15]+1
```
含义是：将地址为15的存储单元的值+1，并将结果写回地址为15的存储单元。  

## 存储程序结构（Stored-program Architecture）
下面的伪代码描述了存储程序计算机的基本操作
```
存储程序计算机
    程序计数器指向存储器中的第一条指令
    REPEAT
        从程序计数器所指的存储单元中读出指令
        修改程序计数器，使之指向下一条指令
        将从存储器中取出的指令解码
        执行指令
    FOREVER
End
```
从存储器中取出的每条指令都需要进行一次访存操作(即读存储器)。
可以用下面的伪代码描述“执行指令”这一动作。
```
执行指令
    IF 指令需要使用数据
        THEN 从存储器中读这个数
    END_IF
    完成指令定义的操作
    IF 指令要将数据写回存储器
        THEN 将数据写回存储器
    END_IF
END
```
存储程序的C语言描述:  
```
InstructionPointer = 0;
do{
    instruction = memory[InstructionPointer];
    decode(instruction);
    fetch(operands);
    execute;
    store(results);
}while (instruction != stop);
```
从上可见，执行一条指令至少需要两次访存。第一次是读取指令。第二次访存要么读数据，要么把之前产生的或修改的数据写回存储器。  

## 指令格式
```
Operation Address1,Address2,Address3
```
Operation: 要执行的指令的动作。  
Address: 操作数的地址。(不是数据本身)  
举例：
```
ADD P,Q,R //P，Q，R均表示地址
```
RTL表示为：
```
[address1]<--[Address2] Operation [Address3]
```
这个例子需要4次访存(取指令，取源操作数x2, 保存结果)  

内存分布：  
```
ADD P,Q,R
[10] [011] [010] [001]
```
10是Op-code，会去Table of operations里面解读：
```
00 Load
01 Store
10 Add
11 Sub
```

Memory:
```
000
001 123 //R  
010 710 //Q  
011 833 //P  
```

对于两地址指令
```
Operation Address1,Address2
```
这里Address1既是源操作数，也是目的操作数  
RTL:
```
[address1]<--[Address1] Operation [Address2]
```
两地址指令会破坏一个操作数。  
两操作数也常常写为：
```
Operation destination,source
```

在实际计算机中，一般不允许同一条指令中使用两个存储地址，大多数计算机都规定一个地址是**存储器地址**，另一个地址是**寄存器**。  

单地址指令  
```
Operation address
```
因为指令需要两个地址，所以另一个地址的操作数来自CPU内一个叫**累加器(accumulator)**的寄存器。  
比如，要实现P = Q + R,其中的Q来自累加器  
首先从累加器中读出Q  
然后把R加到累加器中
最后把累加器的值存到P中
```
LOAD Q
ADD R
STORE P
```

## 计算机分类
按计算机的指令处理数据的方式分类
- 存储器-存储器型：一般计算机不这么做。
- 寄存器-存储器型：比如Intel IA32 CPU体系。结果可以写回寄存器或者寄存器。
- 寄存器-寄存器型：比如ARM和MIPS CPU体系。因为LOAD和STORE是仅有的存储器访问指令，这些计算机也叫load/store型计算机。

由于CPU与存储其性能之间的差距不断加大，通过在使用数据之前将它们从存储器中取出来消除相对慢速的存储器的影响，以降低延迟。

## 存储层次
- 寄存器：32个，速度fastest 1ns
- Cache：8 Mbytes，速度10ns
- DRAM：8 Gbyte，速度40ns
- Hard Disk：1Tbyte，速度20ms=20,000,000ns

Cache：只要cache注意到CPU发出的地址与它保存的某个数据元素地址相同，就把这个数据发送给CPU，而不会去主存中取数据。
- L1 Cache：集成在CPU中。
- L2 Cache：如果L1 Cache查不到，就去查L2 Cache。
- L3 Cache：如果L1/L2都查不到，就去L3查。还查不到就好去主存读了。

DRAM（Dynamic Random Access Memory）：易失性半导体存储器。

## 总线
总线把计算机的两个或多个单元连接在一起，允许它们交换数据。总线还将计算机和外设连接在一起。
- 优点：只有一条高速数据通路，每个单元通过一个接口与这条通路相连。
- 缺点：每次只有唯一一个设备能够与其他设备通信。如果两个设备同请求使用总线，它们不得不去竞争总线的控制权。用术语仲裁来描述多个设备竞争统一资源的过程。

总线宽度：并行数据通路的数量。64位总线表示一次能传送64bit（8bytes）的信息。
总线带宽：衡量信息传送速率的一项指标。数据的单位是B/s or b/s。
总线延迟：从发出数据传输请求到实际数据传输的时间间隔。总线延迟通常包括传输开始之前进行总线仲裁的时间。

多总线系统：片内总线，功能单元间总线，总线间总线等。

## CPU指令集结构
- ARM: RISC
- INTEL: CISC

ISA是CPU设计者设计出来的。  
ISA强调的是功能而不是内部实现。  

ARM这一类CPU采用了存储程序结构。  
这种结构将程序和数据存放在同一个存储空间。  
CPU按照顺序从内存中读指令，译码，执行。  

寄存器位于CPU内部，命名为r0, r1, ..., r15。(ARM命名)  
(INTEL命名为AX, BX, CX, DX, SP, BP , SI...)  
计算机指令的操作码可以用很少的几位来引用寄存器。  
比如16个可见寄存器，可以用4个bit位来引用寄存器。  

寄存器的不同作用
- 高速暂存寄存器：用于保存数据和地址(指针)  
通用寄存器(R1,R2...)  
- 指令寄存器(IR)  
- 循环计数器
- 程序计数器(PC)  
如果一个指令字是32位，则PC每次+4
- 栈指针寄存器
- CPU标识寄存器
- 条件码寄存器(Condition Code Register, CCR)  
保存各种用于测试的条件(零，负，正等)。每当ALU执行一个操作时，会更新CCR中的零位，借位，负位以及溢出位。  
具体来说有Z=zero, N=negative, C=carry, V=overflow  
不同处理器对于更新CCR有不同的规则：INTEL会在每次操作后自动更新；ARM需要在指令中添加后缀S来强制更新(SUBS, ADDS...)(但CMP/TST不需要S也会自动更新)  
- 不可见寄存器  
内存地址寄存器(MAR): 这两个寄存器是在读取存储器的时候，先把内容读到MAR/MBR里。  
内存缓冲寄存器(MBR): 缓存内存的是数据。  
不可见寄存器不属于ISA的一部分，因为程序员不能直接操纵。  

ISA格式
- LDR 寄存器目的，存储单元源
- STR 寄存器源，存储单元目的
- Operation 寄存器目的，寄存器源1，寄存器源2

举例
```
LDR r1,1234     //LDR把存储器复制到寄存器，将地址为1234的存储单元中的数据读到寄存器r1中
STR r2,2000     //STR把寄存器传输到存储器，将寄存器r2的值写入地址为2000的存储单元
ADD r1,r2,r3    //将寄存器r2和r3的内容相加，结果写入r1
```

常量处理  
以下指令把地址为1234的数据存入r1。如果我想直接存入"1234"这个数，该怎么办呢？  
```
LDR r1,1234
```
这种直接存入数据的数字叫做“立即操作数”，前面加个#用来区分  
```
LDR r1,1234      [r1]<-[1234]
LDR r1,#1234     [r1]<-1234
Add r0,r1,#25
```

## 常用指令
类ARM指令
```
LDR r0,address
STR r0,address
ADD r0,r1,r2
SUB r0,r1,r2
BPL target      //如果前一个操作结果大于等于0，则跳转到target处
BEQ target      //如果前一个操作结果等于0，则跳转到target处
B target        //无条件跳转到地址为target处
```

举例，高级语言代码片段如下：
```
X = P - Q
IF X > 0    THEN X = P + 5
            ELSE X = P + 20
```
汇编语言表示：
```
        LDR     r0,p            ;将存储单元P的值加载到寄存器r0中
        LDR     r1,Q            ;将存储单元Q的值加载到寄存器r1中
        SUBS    r2,r0,r1        ;将r0(P)的值减去r1(Q)的值，存到r2(P-Q)里
        BPL     THEN            ;如果r2>=0则执行THEN的部分代码
        ADD     r0,r0,#20       ;否则r0加20，得到P+20
        B       EXIT            ;略过THEN部分跳转到EXIT部分
THEN    ADD     r0,r0,#5        ;否则r0加5，得到P+5
EXIT    STR     r0,X            ;把r0里面的值存到内存单元X里面
        STOP                    ;程序结束
P       DCD     12              ;DCD是定义变量，P是个存储单元，P分配了空间并赋值12
Q       DCD     9               ;Q是个存储单元，Q分配了空间并赋值9
X       DCD                     ;X是个存储单元，X分配了空间
```
另一个例子，在循环中使用条件分支计算1+2+3+...+20
```
        LDR     r0,#1           ;r0用来计数，初始为1
        LDR     r1,#0           ;r1用来存结果，初始为0
NEXT    ADD     r1,r1,r0        ;重复，当前计数值跟部分和相加
        ADD     r0,r0,#1        ;重复，计数器r0加一
        CMP     r0,#21          ;20个数是否都已加完，会更新CCR Z位
        BNE     NEXT            ;直到：完成20次迭代
        STOP                    ;若完成，则程序结束
```

## 寄存储编码举例
ARM的指令是32位的。在指令中用到的opcode和寄存器地址是放不下的。实际上指令里存的是寄存器编码。  
```
opcode&control_bits         Destination register        source_1_reguster        source_2_register
|          17bits          |         5bits            |       5bits            |        5bits          |
```
3个5位的操作数，可以寻址2^5=32个寄存器。  
余下的17位可用于opcode和额外的控制字段。  

## 寻址方式
指令对数据进行操作，必须将数据移动到被处理的地方。指定数据的方式称为“寻址方式”。  
三种基本寻址方式：  
- 立即数寻址：add r1, r2, #5
- 直接寻址：move r0, 1234
- 间接寻址：指令给出了包含操作数地址的寄存器的地址。读取这个操作数需要3次访问：读指令，读含有操作数的寄存器，以及最后读出实际的操作数。含有操作数地址的寄存器被称为指针寄存器。

Load/Store型计算机比如ARM使用这种寻址方式访问存储器操作数。
```
LDR r1, [r2]         ;将寄存器r2所指的存储单元的内容加载到r1
LDR r2, [r3, #8]     ;将寄存器r3+8所指的存储单元的内容加载到r2
```

以下指令分别示例了三地址计算机(ARM)，两地址计算机(INTEL x86)，一地址计算机和零地址计算机  
```
ADD P, Q, R        ;P=Q+R
ADD P, Q           ;P=P+Q
ADD P              ;累加器=P+累加器
ADD                ;从栈顶弹出两个数相加，结果放在栈顶
```
