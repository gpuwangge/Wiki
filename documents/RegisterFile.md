## Register File
register（寄存器）是一个存储位置；register file（寄存器文件/寄存器堆）是一组可按编号访问的寄存器及其读写电路。 换句话说，前者是“一个格子”，后者是“整排格子加上能同时取放数据的接口”。

| 维度   | Register               | Register file              |
| ---- | ---------------------- | -------------------------- |
| 含义   | 单个寄存器                  | 多个寄存器组成的阵列                 |
| 例子   | r1、x5、一个 32-bit PC 寄存器 | 32 × 32-bit 的通用寄存器组        |
| 访问方式 | 通常就是读/写这一个固定位置         | 通过地址/索引选择其中一个，如 rs1=1 读 r1 |
| 硬件实现 | 可由触发器、锁存器或专用存储单元实现     | 常实现为小型、多端口的 SRAM-like 阵列   |
| 常见端口 | 单个数据输入/输出和使能信号         | 多读端口、至少一个写端口，支持并发访问        |

例子  
若 CPU 有 32 个 64-bit 通用寄存器：
```
x0, x1, x2, ... x31
```
那么：  
x7 是一个 register。  
所有 x0 到 x31 加上“通过 5-bit 索引选择任一个寄存器”的逻辑，是一个 register file。  
5-bit 是因为 2^5=32  

对于：
```
add x3, x1, x2
```
CPU 通常从 register file 的两个读端口并行读 x1 与 x2，经 ALU 计算后，通过写端口把结果写回 x3。一个典型设计正是 2 read ports + 1 write port。  

一个容易混淆的点  
某些专用寄存器不一定属于通用 register file，例如 PC、状态寄存器、控制寄存器、GPU 的某些特殊硬件寄存器；它们可能独立实现。  
相反，CPU 也可能把部分特殊寄存器纳入 register file，具体取决于微架构。  
在 GPU 语境里，大家口头说“这个 shader 用了 80 registers”，通常指每线程需要 80 个逻辑寄存器；  
这些值最终占用 SM 上共享的物理 register file容量。寄存器使用量越高，能并发驻留的线程块可能越少。
