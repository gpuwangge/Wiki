# Warp Divergence
Warp divergence（分支发散）指同一个 warp 内的线程，对 if/else 条件得出了不同结果。  
GPU 的 SIMT 执行模型不能让同一个 warp 在同一个时刻执行两条不同的指令流：它会先执行 if 路径、屏蔽走 else 的 lane，再执行 else 路径、屏蔽走 if 的 lane，最后在控制流汇合点重新合流。  
因此耗时接近两条路径的总和，而不是二者之一。  

## 例子1
把 GPU 想成一个老师，带着 64 个小朋友 一起画画；每 32 个小朋友是一个 组(warp)。  
其中32个小朋友穿红衣服，画苹果；另外32个小朋友穿绿衣服，画香蕉。每个组都是红蓝衣服小朋友各一半。    
```
warp 1：红 16，蓝 16  
warp 2：红 16，蓝 16  
```
原始做法：
```
warp 1：画苹果，只有 16 人工作
warp 1：画香蕉，只有 16 人工作

warp 2：画苹果，只有 16 人工作
warp 2：画香蕉，只有 16 人工作
```
总共做了 64 人份画画，但 GPU 的“座位”使用了128  

分队 / BFS 做法  
先不立刻画，而是从所有 warp 收集任务：  
```
苹果队：warp 1 的红 16 + warp 2 的红 16 = 32
香蕉队：warp 1 的蓝 16 + warp 2 的蓝 16 = 32
```
现在是 2 次满的工作：
```
warp 1: 苹果 32
warp 2: 香蕉 32
```
同样完成 64 人份画画，但只使用：64个座位。这里节约了一半的执行槽位。  

## 例子2
假设每个小朋友要经过三关：  
```
第 1 关：看衣服颜色
第 2 关：红衣服画苹果，蓝衣服画香蕉
第 3 关：交作业
```
不按 BFS：每个人从头做到尾  
```
1号：看颜色 → 画苹果 → 交作业
2号：看颜色 → 画香蕉 → 交作业
3号：看颜色 → 画苹果 → 交作业
```
GPU 的一个 warp 同时处理这些人时，第 2 关就混杂了苹果和香蕉，于是发散。  

按 BFS：先完成同一关，再决定下一关  
```
第 1 轮：所有人只看衣服颜色

分队：
苹果队：收集所有红衣服小朋友
香蕉队：收集所有蓝衣服小朋友

第 2 轮：
苹果队一起画苹果
香蕉队一起画香蕉

第 3 轮：
所有完成的人交作业
```

这里的关系是：  
```
BFS：提供“第 1 轮结束”的统一集合点
分队：在这个集合点，把下一轮要做不同工作的任务拆开
```
所以，BFS 让你有机会说：“先停一下，把这一层的结果收集起来、分类，再开始下一层。”   
如果每个小朋友都在一个大 shader 里从头跑到尾，你也能分队，但实现起来会困难很多。  
BFS 是“大家先一起做第几关”的流程；分队是“到了下一关前，把做不同题的人拆开”的优化。  

## 例子3
假设有 128 个数字，GPU 每 32 个一组，共 4 个 warp：
```
// 每个线程处理一个 x[i]
if (x[i] > 0.0) {
    y[i] = a[i] * b[i] + c[i]; // A：FMA
} else {
    y[i] = x[i] - d[i];        // B：减法
}
```
并假设每个 warp 都是正负各 16 个：
```
warp 0：16 个 x > 0，16 个 x <= 0
warp 1：16 个 x > 0，16 个 x <= 0
warp 2：16 个 x > 0，16 个 x <= 0
warp 3：16 个 x > 0，16 个 x <= 0
```
那么每个 warp 都必须这样执行：
```
第 1 小步：16 个线程做 FMA，另 16 个等待
第 2 小步：16 个线程做减法，另 16 个等待
```
所以 4 个 warp 共经历：
```
FMA 半满 × 4
减法 半满 × 4
```
即 8 次“半载”执行
